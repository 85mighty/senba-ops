# Kobe Gallery Studio — Scaniverse 3D 복원 및 인테리어 시뮬레이션

> **Claude Code 작업 지시서 (2026-10-26)**  
> 목적: 사용자가 iPhone LiDAR / Scaniverse로 촬영한 **실제 고베 점포의 3D 스캔**을 기준으로, 원본과 동일한 공간 배치를 최대한 보존한 정돈된 3D 모델과 비교 가능한 인테리어 시뮬레이터를 제작한다.  
> **한국어로 소통하고, 작업·설치·실행 방법은 Mac 사용자에게 쉽게 안내할 것.**

## 0. 가장 중요한 원칙

1. **새 매장을 상상해서 재생성하지 말 것.** Scaniverse OBJ/GLB는 실측에 가까운 **형상 근거**, 원본 실내 사진은 **위치·재질·상세 근거**이다. 둘을 비교해 정확한 기둥/창문/문/주방 위치를 재구성한다.
2. LiDAR 데이터의 찢어짐/구멍/떠 있는 노이즈는 정상적으로 흔히 발생한다. **실제 구조물과 스캔 노이즈를 분리**하고, 고쳐야 하는 메시는 별도 레이어/파일로 다룬다. 자동으로 노이즈를 지우다가 진짜 기둥이나 벽을 삭제하지 말 것.
3. **스캔에 없는 부분은 추정치**이다. `measured / observed / inferred` 등의 구분, 수정 가능한 치수/위치, 불확실한 곳의 표기를 유지할 것. 정밀 건축 도면이 아니며 공사 전 현장 실측 필수.
4. 기존 나무 바닥, 회색 벽지, 검은 중간 가로 띠(체어레일), **맨 아래 검은 걸레받이**를 유지한다. 사용자의 명시적 승인 없이 철거·색 변경 금지.
5. **중앙에 있는 넓고 큰 가벽/기둥 1개에만 사방(4면) 거울**을 추가한다. 모든 얇은 기둥을 거울로 바꾸지 않는다.
6. 사용자 목표는 **공사량/비용을 줄이면서 고급스러운 미술관·아트 체험공방 느낌**을 만드는 것. 화려한 완전 개조보다 실제 시공 가능한 최소 변경이 우선.
7. 기존 모델/파일을 덮어쓰지 말고 `original`, `cleaned`, `reconstructed`, `interior_A`를 따로 유지하여 A/B 비교한다.
8. 결과가 실제로 동작하는지 **브라우저에서 로딩·시점·전환을 테스트**한다. 다운로드만 제공하고 검증 생략하지 말 것.

## 1. 입력 파일과 현재 작업 상황

사용자는 Mac / Chrome / Python 3 로컬 서버를 사용하며, `~/Downloads`에서 다음처럼 서버를 실행해 3D 뷰어를 본 적이 있다.

```bash
cd ~/Downloads
python3 -m http.server 8000
# Chrome: http://localhost:8000/...
```

### 주요 파일 (Mac의 `~/Downloads`에서 실제 존재 여부 확인)

| 파일 | 역할 |
| --- | --- |

| `scaniverse_actual_space.glb` | 원본 OBJ + 텍스처에서 변환한 실제 스캔 기반 GLB. 기존 뷰어에서 표시 성공. |

**주의:** 이 파일명은 이전 작업에서 사용된 이름이다. 실제 Mac 폴더에서 확인하라. 입력 ZIP 내부의 OBJ/MTL/JPG 관계를 검사하고, 텍스처 유실 없이 불러와야 한다. 내장 이미지가 아닌 사진도 필요하면 사용자가 가지고 있는 인테리어 촬영 사진을 `reference_photos/` 폴더로 복사하도록 안내한다.

Scaniverse ZIP의 내부 파일 이름(사용자가 전달한 원본 기준):

```text
Scaniverse 2026-10-26 113837/
  Scaniverse_2026_10_26_113837.obj
  Scaniverse_2026_10_26_113837.mtl
  Scaniverse_2026_10_26_113837.jpg
```

이전 대화에 나온 스캔 정점 약 12만·삼각형 약 16만과 매장 크기 약 8.7m × 10m × 3.1m는 **기존 분석의 참고 수치**일 뿐이다. 파일을 직접 검증하고 OBJ/GLB의 좌표 단위, 원점, 스케일 및 bounding box를 먼저 계산한다. 높이 3.1m를 실제 천장고로 단정하지 말 것.

## 2. 실제 공간에서 보존해야 할 것

- 원목처럼 보이는 **중간~진한 갈색 우드 패턴 바닥**: 교체하지 않는다.
- 약간 질감 있는 **회색 벽지**: 대부분 그대로 두고, 실제 벽면 색/표면 표현을 우선한다.
- 벽 중간을 가로지르는 **검은색 띠**와 바닥의 **검은색 걸레받이**: 위치와 색을 유지한다.
- 길게 이어지는 반투명/불투명 유리 창, 창틀/창 아래 벽, 입구, 부속 주방/싱크, 타일 마감 공간 및 화장실 출입문.
- 매장 중앙 부근의 **넓은 가벽형 기둥(주요 거울 대상)** 및 주변의 여러 개 **상대적으로 얇은 구조 기둥**: 서로 구분한다.
- 천장의 검은 트랙레일, 흰색 행잉 레일, 카세트 에어컨, 조명 등 기존 설비는 사진으로 확인하고 보존한다.
- 장애물/기둥을 관통하는 동선이 생기지 않도록 한다. 입구, 주방, 화장실로 가는 통로 폭을 확인한다.

**필수 검증:** 원본 사진에서 기둥의 모양이 넓은 벽체형인지 사각 기둥인지, 각 면이 바닥/천장까지 닿는지 확인. 스캔 좌표와 이미지에 근거해 `central_wide_column` 하나만 식별하며 애매하면 모델에서 해당 오브젝트를 클릭해 위치를 선택·변경할 수 있게 한다.

## 3. 목표 인테리어 — A안 (기본)

### 반드시 유지

- 기존 바닥 **그대로**
- 검은 중간 가로 띠 **그대로**
- 바닥과 만나는 검은 걸레받이 **그대로**
- 원래 회색 벽지 **가능한 그대로**
- 창문, 기둥/벽 구조, 기존 설비/문 위치 **그대로**

### 새로 추가

- 검은 중간 띠와 검은 하부 걸레받이 **사이 영역**에 클래식한 **화이트 사각 프레임 몰딩(웨인스코팅 분위기)**을 설치. 검은 띠를 흰색으로 바꾸는 게 아니다.
- 기본 렌더링은 **회색 벽지 위에 흰색 얇은 프레임**을 붙인 저공사 버전. 선택 옵션으로 `하단만 화이트 패널 마감` 토글을 제공하되 기본은 OFF.
- 큰 가벽 기둥 **4면에 안전한 전신 거울**을 붙이는 안을 3D로 표시. 사방에서 거울처럼 보이도록 렌더링하되 반사 연출은 실시간 성능과 충돌하지 않게 구현(실제 `Reflector` 또는 `cube capture`/환경맵의 장단점 확인). 하단 걸레받이와 전기 설비 간섭 확인.
- 클래식 골드 액자 형태의 작품 디스플레이 및 따뜻한 화이트 트랙 조명. 참조한 미술관 사진은 **색감/전시 분위기 참고**이지 실제 원본 작품을 그대로 복제하라는 뜻이 아님. 저작권/사용 허가 고려.
- 부분적인 와인색/테라코타 포인트 벽 **별도 ON/OFF** 옵션. 사용자 승인 전에는 기본 **OFF**. 점포 전체를 붉은색/주황색으로 만들지 말 것.
- 테이블·스툴·작품 진열대는 별도 `furniture` 그룹으로 구성하고 ON/OFF. 사진/실측되지 않은 임의의 테이블 위치는 편집 가능해야 함.

### 디자인 방향

- 키워드: **modern classic museum / warm gallery / cost-conscious renovation**.
- 검은 기존 띠 + 화이트 패널 프레임 + 회색 상부 + 갈색 바닥 + 금색 액자의 균형.
- 작품 감상과 실제 체험 수업 동선이 방해되지 않도록 전시 위치와 테이블 수를 조절.

## 4. 실행할 개발 작업 순서

### Phase 1 — 원본 검증과 좌표 정렬 (가장 먼저)

1. 로컬에서 Scaniverse 원본 ZIP, GLB를 찾고 무결성 확인. 원본은 `assets/original/`에 복사한 후 그대로 보관.
2. Python `trimesh` (필요시 `open3d`) 또는 Blender `bpy`를 사용해 OBJ/GLB 메쉬/머티리얼/텍스처/좌표계 분석. 파일 단위가 m인지 mm인지 검증.
3. 바닥면의 법선/평면과 중력 방향을 정하고 **바닥을 XY 또는 XZ 기준의 높이 0**에 정렬. 이전 파일의 임의 회전/뒤집힘이 있는지 확인.
4. 삼각형 개수, 컴포넌트별 크기, bounding box, 카메라에 따른 공간 방향, 바닥/벽/창문/기둥 후보 좌표를 `reports/scan_analysis.md`와 그림으로 출력.
5. 참조 사진의 시점과 3D 배치가 어느 정도 맞는지 3~5개의 카메라 북마크로 검증. 틀린 구조가 발견되면 인테리어보다 **구조 수정 우선**.

### Phase 2 — 정리된 스캔 모델

1. 파편/고립된 섬 컴포넌트를 **크기, 면적, 주변 구조와의 거리**로 분리하되, 일괄 임계값으로 삭제하지 말 것.
2. 벽/바닥/천장/기둥/창문을 용도별로 구분. 기존 스캔 텍스처를 보존한 `clean_scan.glb` 제작.
3. 사용자가 `원본 ↔ 노이즈 정리`를 스위치로 비교할 수 있도록 뷰어 구성.
4. 삭제된 파편 목록과 임계값을 기록하고, 필요하면 되돌릴 수 있는 파이프라인 작성.

### Phase 3 — 정돈된 건축 모델 (핵심)

1. 바닥과 주요 벽에 대해 plane fitting (RANSAC 등)으로 평면 후보를 찾아 정확한 방위와 위치를 얻는다.
2. 사진 + 스캔 모두에서 확인한 벽, 기둥, 창문, 문틀 등을 우선 **매끈한 메쉬**로 재구성한다. 불명확한 영역은 임시 재구성으로 구분한다.
3. `clean_scan.glb` 위에 임의의 벽을 그냥 덮어서 공간 배치가 왜곡되지 않게 한다. 원본/복원본을 **같은 월드 좌표**에서 독립 토글 비교하도록 한다.
4. 실제 나무 바닥과 비슷한 색, 회색 벽지, 검은 띠를 적용해 `reconstructed_room.glb` 제작. 기존 텍스처가 충분히 좋으면 재활용.
5. 중앙 넓은 기둥을 식별하고 네 면의 가로·세로/방향·주변 충돌을 별도 객체 및 메타데이터로 저장.
6. 가능하면 측정/추정 포인트별 상태를 `labels.json` 또는 `geometry_metadata.json`에 기록.

### Phase 4 — 인테리어 A안 적용

1. `interior_A` 변형을 실제 구조물 좌표에 추가; 원래 메쉬는 수정하지 않는다.
2. 하부 흰색 사각 프레임은 **벽 길이, 높이, 콘센트, 문, 창 아래 높이**를 고려해 세그먼트별 자동 생성. 벽에 맞게 45도 코너, 적절한 간격, 고르게 분포되게 함. 검은 중간 띠/걸레받이 위에 덧칠하지 않는다.
3. **중앙 넓은 기둥 4면 거울**을 평탄하게 부착해 시각화하고, 위치/크기 편집 컨트롤 추가. 예산 친화적인 실제 시공 방식으로는 비산방지 필름, 모서리 보호, 기존 콘센트/점검구 간섭, 화재/피난 동선 등도 체크리스트로 표시.
4. 작품 전시 액자, 트랙 조명 밝기/색온도, 체험 테이블을 별도 그룹으로 배치.
5. `wall_gray / panel_white_optional / wine_accent_optional / gallery_art / furniture / mirror_4_sides` 토글 구현.
6. `interior_A.glb` (또는 뷰어에서 동적으로 변형되는 구조) 및 비교 이미지 4~6장 생성.

### Phase 5 — 브라우저 3D 뷰어

- 브라우저: Mac Chrome 우선, 가능하면 iPhone Safari도 동작.
- 기술: Three.js + GLTFLoader + OrbitControls; 필요시 Blender `bpy`로 베이크/노멀/텍스처 보정. 라이브러리는 **버전 고정**, 패키지 매니저/Vite 사용을 권장.
- 모델은 `assets/models/`에 두고, 참조 경로는 상대경로로 지정. 과거 문제였던 **HTML과 GLB 파일명 불일치/서로 다른 폴더** 재발 방지.
- 모드 버튼: `① 원본 스캔`, `② 노이즈 정리`, `③ 공간 보정`, `④ 인테리어 A안`.
- 조작: 회전·줌·팬, 카메라 북마크(입구/메인/창가/주방/큰 기둥), 미니맵(선택), 중심 기둥 강조.
- 가능하면 `단면/천장 숨기기`, `전후 비교`, `거울 ON/OFF`, `프레임 몰딩 ON/OFF`, `치수표시` 제공.
- 브라우저에서 GLB가 보이지 않으면 404, CORS, GLB loader, 그래픽 콘솔 오류를 분리해 표시. 검은 화면/`로딩 중` 무한 대기 금지.
- 성능: 메쉬 수 적정화, draw-call 축소, 모바일 pixel ratio 제한. **원본의 실제 치수와 기둥 위치는 유지**한 채 최적화.

구조는 환경에 맞게 조정 가능하되, **원본 보존, 모델별 분리, 실행 명령의 재현성**은 필수.

## 6. Claude Code가 처음 해야 할 일

1. 터미널에서 사용자의 현재 작업 디렉터리를 확인하고, `~/Downloads`에 있는 실제 모델 파일/ZIP 목록을 보여준다.
2. 원본 Scaniverse ZIP을 찾지 못하면 **사용자가 가진 원본 파일의 정확한 경로**를 한 번만 묻는다. 나머지는 찾을 수 있는 파일로 먼저 시작한다.
3. `scripts/inspect_scan.py`를 실행해 스캔의 바닥/벽 방향과 축·단위를 확인하고, 구조 진단 이미지를 만든다.
4. 원본과 사진의 차이가 나는 이유를 **구조 추정 오류 vs LiDAR 누락/노이즈**로 구분해 설명한다.
5. 1차 목표는 꾸미기 전 **원본과 같은 레이아웃의 깨끗한 모델**이며, 이 검증 후 A안 인테리어를 추가한다.

### Mac 실행 예시

```bash
# Claude Code가 준비한 프로젝트로 이동
cd ~/Downloads/kobe-gallery-3d

# Claude Code가 생성한 프로젝트의 package.json을 확인한 뒤 실행
npm install
npm run dev
```

최종 URL은 Vite나 다른 서버에서 실제 출력한 `http://localhost:<port>/`를 안내한다. **기존 `localhost:8000` 주소를 강제하지 말 것**. 만약 정적 HTML + GLB만 사용한다면 같은 폴더에서 `python3 -m http.server 8000`으로 실행 가능하게 구성한다.

## 7. 완료 조건 (Acceptance criteria)

- [ ] 원본 ZIP/GLB를 열어 실제 삼각형/정점 수, bounds 및 단위를 확인했다.
- [ ] 사용자 원본 사진의 공간 배치가 3D와 일치하는지 카메라 시점 최소 3개로 대조했다.
- [ ] 중앙 넓은 가벽과 얇은 기둥을 구분해 각기 제 위치에 둔다.
- [ ] 스캔 파편이 제거되었지만 실제 벽·기둥·주방·창문은 손상되지 않았다.
- [ ] 복원된 벽/천장에 생긴 임의의 구멍·겹침·뒤집힌 면이 없다(남은 부분은 표시).
- [ ] 원래 바닥색, 회색 벽, 검은 가로 띠, 검은 걸레받이가 **기본 보기에서 유지**된다.
- [ ] 하부 화이트 사각 몰딩만 추가하는 A안 구현; 기존 검은 띠 유지.
- [ ] 중앙 넓은 기둥 **1개 4면 거울** 구현; 나머지 기둥은 그대로.
- [ ] 선택 사항(와인색 포인트 벽/가구/작품)은 토글이며 기본 변경값을 강요하지 않는다.
- [ ] 원본/정리/복원/A안 전환 시 카메라 위치가 유지돼 전후 비교가 가능하다.
- [ ] Chrome에서 텍스처 포함 GLB 로딩 성공, 콘솔 404 에러가 없다.
- [ ] 미리보기 스크린샷·영상 또는 브라우저 테스트 로그로 작동 검증.
- [ ] 설치 방법과 최종 파일 위치를 한국어 README에 제공.

## 8. 바로 실행할 첫 작업 요청

**먼저 원본 Scaniverse ZIP부터 조사하고 실제 기둥/벽/바닥/창문의 공간 배치를 복원해줘.** 기존의 사진만 보고 대충 만든 가상 공간과 다른 모델이므로, 상상으로 기둥이나 창문을 추가하면 안 돼. 원본 텍스처·원본 모델은 보존하고, 같은 좌표를 공유하는 노이즈 정리판과 벽면 보정판을 만들어 실제 Chrome 3D 뷰어에서 원본과 즉시 비교 가능하게 해줘. 그 다음 바닥/검은 띠/회색 벽지를 유지하고, 검은 띠 아래 흰색 사각 몰딩과 중앙 넓은 기둥 4면 거울을 적용하는 A안으로 확장해줘. **완료되었다고 말하기 전에 실제 실행 화면/콘솔 오류를 검증해줘.**
